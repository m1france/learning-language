# Audit du dépôt — 1 novembre 2026

## Conclusion

L'ancien déploiement ne doit pas être remis en ligne tel quel. Les API de partage étaient ouvertes en lecture/écriture/suppression, sans notion de propriétaire. Plusieurs bricolages de migration pouvaient effacer des données locales, tandis que l'installation Docker utilisait des secrets par défaut et des fichiers compilés préexistants.

Le dépôt contient maintenant un déploiement **privé pour un propriétaire**, protégé par HTTPS et mot de passe Caddy. Il ne constitue pas une plateforme publique multiutilisateur. Aucun accès SSH, aucune lecture de données privées distantes et aucune publication n'ont été effectués : le propriétaire exécutera le [guide Oracle](DEPLOIEMENT_ORACLE.md).

## Périmètre et méthode

Référence de départ : `de90a5ad402a9c22d97b539c9960a97438a4597a`, arbre de travail initial propre.

- Inventaire de tous les fichiers du dépôt ; analyse AST et graphe des imports de toutes les sources TS/TSX, inventaire CSS/SQL, revue du HTML, des configurations et des dépendances des deux projets. Environ **69 500 lignes**, **123 fichiers source CSS/SQL/TS/TSX** après corrections ; les images et bundles compilés ne sont pas comptés comme du code source à relire.
- Revue approfondie des chemins sensibles : serveur et toutes ses routes, persistance, imports de ressources, rendu HTML/SVG, agent et outils, appels IA/transcription/DeepL, audio/caméra, partage de leçons et déploiement.
- Compilation frontend/backend ; diagnostic TypeScript des déclarations inutilisées ; audit npm des deux lockfiles auprès du registre ; recherche de motifs de clés privées et clés API sans afficher de valeurs.
- Tests HTTP locaux sur des données fictives et dossier temporaire ; vérification du chargement dans le navigateur au format desktop et 390 × 844.

C'est une revue statique globale accompagnée de tests ciblés, pas une certification de chaque parcours métier. Les traductions et styles ont été inventoriés ; tous les états visuels, langues, gros volumes, fournisseurs payants, anciennes données et configurations MySQL n'ont pas été exécutés. L'historique Git complet n'a pas fait l'objet d'une recherche de secrets.

## Sécurité et fiabilité

| ID | Gravité initiale | Constat et preuve dans le code | État |
| --- | --- | --- | --- |
| S1 | Critique si accessible publiquement | `server/src/index.ts` : POST fait un upsert sur un ID fourni par le client ; DELETE supprime tout ID ; GET sans username retourne toutes les leçons. Aucun contrôle d'identité/propriété. | **Accès anonyme bloqué dans le déploiement privé** : Caddy authentifie toutes les routes et injecte un secret ; le backend exige ce secret en production. Les droits entre utilisateurs restent absents. |
| S2 | Élevée | `index.html` et `src/store.ts` effaçaient des clés selon le nom « Mathis », des IDs fixes ou l'ancien domaine. Les paramètres `?owner=mathis`, cookies et en-têtes IP servaient de pseudo-identité. Ce n'était pas une authentification. | **Corrigé** : purge et pseudo-identité supprimées, injection/cookie serveur retirés. Pas d'effacement de données existantes pendant l'audit. |
| S3 | Élevée | Ancien plugin dans `vite.config.ts` : GET/POST `/api/sync` exposaient l'état global, incluant potentiellement `settings.api`, alors que le serveur de production désactivait la sync. Vite écoutait sur toutes les interfaces. | **Corrigé** : plugin supprimé ; développement limité à loopback par défaut. Aucun fichier de sync réel n'a été consulté. |
| S4 | Élevée | Pas de limite de corps ; commentaires/stickers illimités ; champs JSON sans validation ; écritures fichier échouées néanmoins présentées comme réussies ; JSON corrompu remplacé potentiellement par un nouvel état vide. | **Réduit** : corps API 2 Mio ; IDs/usernames contrôlés ; textes 4 000 caractères et auteurs 80 ; positions contrôlées ; 200 leçons, 500 interactions par collection/leçon, 50 types de réaction, fichier 20 Mio ; écriture atomique par renommage ; échec explicite et conservation du fichier corrompu. Il manque encore un schéma complet de leçon et une limitation du débit. |
| S5 | Moyenne à élevée selon l'entrée | `LearningFocus.tsx` interpolait `run.c` directement dans un attribut HTML avant `innerHTML`. Un attribut de couleur forgé pouvait sortir de l'attribut. | **Corrigé** : construction de spans par DOM, affectation via `style.color` et `textContent`. La provenance distante de cette entrée n'a pas été démontrée par un exploit de bout en bout. |
| S6 | Moyenne | `HtmlArtifact.tsx` annonçait « no network » tout en autorisant des images HTTPS et formulaires. Une image pouvait transmettre du texte connu du modèle à un tiers. L'insertion de la CSP dans un HTML arbitraire pouvait arriver après des éléments fournis par le modèle. | **Durci** : CSP placée avant le code, images limitées à data/blob, formulaires interdits, iframe sans `allow-forms`. L'origine opaque et le contrôle de `event.source` existaient déjà et sont conservés. Pas de garantie totale contre toute navigation d'un HTML arbitraire ; utiliser des composants déclaratifs pour des contenus sensibles. |
| S7 | Moyenne | `assistantTools.ts:132` exécute une regex libre fournie à l'outil IA dans le thread UI. `(a+)+$` sur 31 caractères a dépassé un délai de 500 ms dans un sous-processus isolé. Les flags `g/y` conservent aussi `lastIndex` entre phrases, ce qui rend les résultats instables. | **À corriger** : exécuter dans un Worker terminable avec limites, ou supprimer l'entrée regex libre. Blocage local plausible, pas une exécution de code sur le VPS. |
| S8 | Moyenne | `src/importer.ts` transmet les URLs importées à trois relais CORS publics en cas d'échec direct, puis peut transmettre le HTML à un fournisseur IA. Une URL avec un token peut donc être divulguée. | **À corriger** : consentement explicite aux relais, refus des URLs authentifiées/privées, ou service d'import maîtrisé. Ce n'est pas une SSRF serveur démontrée : les imports actuels partent du navigateur. |
| S9 | Moyenne | Clés de services dans `settings.api`, persistées en clair dans localStorage ; appels IA depuis le navigateur. Tout script exécuté dans l'origine et toute personne disposant du profil navigateur peuvent les lire. | **Architecture conservée** pour l'usage personnel ; aucune clé serveur embarquée dans le frontend n'a été ajoutée. Pour un service partagé : coffre serveur, comptes, quotas et proxy avec liste d'endpoints autorisés. |
| S10 | Moyenne | Imports EPUB/PDF et décodage audio chargés en mémoire, sans limite globale de taille/durée/décompression. | **À corriger** : limites avant lecture, budgets de décompression et durée, traitement en Worker/streaming. Un fichier compressé de petite taille peut néanmoins se décompresser fortement. |
| S11 | Moyenne | `server/src/index.ts` entretient deux sources de vérité quand DATABASE_URL est présent : certaines lectures préfèrent MySQL, les interactions partent du JSON, les erreurs DB sont seulement journalisées. Les flags `allowComments`/`allowReactions` ne sont pas imposés par les routes. | **Hérité, non corrigé** ; MySQL n'est pas activé par le Compose fourni. Retenir un seul stockage et faire respecter les permissions avant toute ouverture publique. |
| S12 | Fonctionnelle élevée | `teacherExportService.ts:128` sauvegarde localement puis fait un fetch en arrière-plan sans tester `response.ok`. L'écran de succès apparaît avant confirmation serveur. Les interactions peuvent envoyer à la fois une leçon complète et une requête de commentaire/réaction, avec double comptage/écrasement possible. `fetchSharedLesson` privilégie indéfiniment le cache local. | **À corriger** : API async confirmée, erreurs visibles, mises à jour atomiques ciblées et revalidation du cache. Vérifier manuellement la publication lors du déploiement. |
| S13 | Fonctionnelle / confidentialité | `resolveLlm` peut choisir un autre fournisseur si la clé préférée manque ; la transcription OpenRouter possède encore une liste de modèles de secours. Les routes IA sont dupliquées entre `getAgentConfig` et `resolveLlm`. | **À harmoniser** : aucun changement automatique de fournisseur/modèle configuré ; afficher la route réellement utilisée. Le test du Coach prouve seulement l'absence de secours caché pour ce Coach, pas pour tous les services IA. |

Précisions : les requêtes SQL examinées utilisent des paramètres pour les valeurs utilisateur ; aucune injection SQL exploitable n'a été démontrée. Les rendus Markdown de vocabulaire et notes échappent le texte ; la simple présence de `innerHTML` ne prouve pas une XSS. Le SVG IA est affiché comme image, pas injecté comme DOM actif. Le sandbox iframe et les requêtes SQL paramétrées sont des protections déjà présentes.

## Code mort et dette technique

Le diagnostic initial TypeScript trouve **128 déclarations/imports/paramètres inutilisés**, détaillés dans `audit/unused-before.txt`. Cela inclut des imports React inutiles avec le JSX automatique et des paramètres d'API publique : ce nombre n'est pas un nombre de fonctionnalités cassées.

Cinq modules ne sont atteignables ni depuis `src/main.tsx` ni depuis le serveur dans le graphe des imports statiques et dynamiques littéraux :

| Module | Lignes approximatives | Interprétation |
| --- | --- | --- |
| `src/seed.ts` | 51 | Anciennes entrées culturelles et outils recommandés |
| `src/features/speaking/ImprovWheel.tsx` | 284 | Ancien composant de roue orale |
| `src/features/writing/WritingHistory.tsx` | 243 | Ancien écran d'historique |
| `src/features/writing/WritingSetupModal.tsx` | 381 | Ancien paramétrage d'écriture |
| `src/features/exercises/exerciseStorage.ts` | 73 | Couche IndexedDB d'historique des exercices non utilisée |

Ils sont identifiés mais conservés comme sources tant que leur suppression fonctionnelle n'a pas été décidée. Leur absence d'import signifie qu'ils ne sont normalement pas livrés dans le bundle. Aucun chargement par nom calculé n'a été identifié pour ces fichiers.

`features/sync/syncService.ts` est encore importé par Settings mais n'est plus un service de synchronisation : push ne fait rien et retourne un succès ; pull lit le stockage local ; l'ancien merge et les champs/timers sont inactifs. `syncInfo` et `handleManualSync` ne servent à aucun affichage. Supprimer cette couche ou la remplacer par un vrai statut « stockage local ».

Les anciens artefacts suivis dans Git (`dist`, `server/dist`, `vite.config.js`, déclarations et caches TypeScript, `.DS_Store`) brouillent la source de vérité. Le déploiement ne doit jamais reprendre un ancien bundle. Les fichiers générés sont exclus, le build ne réémet plus de configuration JS à côté du TS, et les artefacts de départ sont retirés du dossier de travail en fin de validation. Ils seront reconstruits par Docker ; aucun nettoyage de l'historique Git n'a été effectué.

Après mise à jour de l'outillage et corrections, le chunk principal fait environ **1 003 ko / 318 ko gzip**. Ce n'est pas une optimisation du chargement : la répartition des chunks a aussi changé. Le warning > 500 ko reste présent.

## Corrections de déploiement livrées

- Docker multiétape depuis les sources, Node 24 LTS ; retrait de l'installation FFmpeg/yt-dlp, non utilisés par le backend actuel. Node 20 de l'ancien Dockerfile est arrivé en fin de support selon le [calendrier Node](https://nodejs.org/en/about/previous-releases).
- Remplacement du Compose MySQL/Node ouvert par Caddy + Node privé, volume durable des leçons, healthcheck, logs bornés, utilisateur Node non root, capabilities retirées et rootfs en lecture seule pour l'application.
- Ancien montage `./server/db-init.sql` erroné retiré ; le vrai fichier était `server/src/db-init.sql` et ne créait qu'une table users inutilisée. Plus aucun mot de passe MySQL par défaut dans Compose.
- `.dockerignore`, `.env.example`, exclusion des données, secrets et anciens builds.
- Liens générés sur le domaine courant `/share/...`, exemples d'URL visibles corrigés ; compatibilité de lecture des anciennes URLs conservée.
- Retrait des CORS globaux, validation JSON, erreurs de route API en JSON 404, MIME `.mjs` pour le worker PDF, suppression des marqueurs propriétaire.
- Proxy DeepL à hôtes et chemin fixes, avec timeout et entrées bornées. Clé dans `X-DeepL-Key` côté requête locale pour éviter le conflit avec Basic Auth ; Authorization DeepL uniquement vers l'upstream. DeepL confirme que les appels directs navigateur sont [bloqués par CORS](https://developers.deepl.com/docs/best-practices/cors-requests). Ce proxy ne transforme pas les clés locales en coffre de secrets serveur.
- Retrait de l'interdiction de zoom dans le viewport HTML.

## Validation et limites

Validés localement :

- `npm run build` et `npm run build:server` ; warning de taille frontend conservé et documenté.
- `npm run test:coach` : modèle explicite, audio transmis quand prévu, absence de secours caché du Coach, payload texte pour modèle texte.
- `npm run test:security` : production refuse une configuration sans token ; toutes les routes protégées ; mauvaise origine 403 ; IDs réservés/type incorrect refusés ; JSON invalide 400 ; corps > 2 Mio 413 ; publication/lecture/commentaire/réaction/commentaire positionné/sticker ; rejet des mauvaises positions ; 404 API, MIME mjs, absence de cookie propriétaire et de CORS wildcard ; conservation après redémarrage ; dépublication ; corruption non écrasée. Proxy DeepL free/pro testé avec un faux upstream, sans clé réelle et sans appel externe.
- `npm audit` dans les deux projets : **0 vulnérabilité signalée**, résultats conservés.
- `docker compose config --quiet` avec valeurs fictives : configuration Compose valide.
- Navigateur local : accueil chargé et console sans erreur/avertissement capturé ; largeur de document 390 pour viewport 390 × 844, aucun débordement horizontal sur l'accueil. Pas de validation de tous les écrans mobiles.
- `git diff --check`.

Non validés : build/exécution Docker (daemon Docker local absent), validation effective du binaire Caddy, architecture/capacité/OS du VPS, DNS, pare-feu, certificat HTTPS, migration des anciennes données, backend MySQL, API payantes réelles, caméra/micro réels, charge, protection contre force brute et parcours métier exhaustifs. Les commandes du guide incluent les vérifications de déploiement à effectuer sur le VPS.

Avant un service public : comptes et droits propriétaire/lecteur, corrections S7/S8/S11/S12/S13, validation complète de schéma, quotas/débit, sauvegarde/restauration de toutes les données et tests de ces garanties.
